Conceptual architecture brief

Answers you can trust, from data you control.

Ask Nanci gives merchants and partners a simple way to explore payments data without giving the AI direct access to that data. Identity, access rules, data protection, and monitoring work together at every step.

PCI DSS Compliant OWASP aligned MITRE ATLAS guided NIST AI RMF informed ISO/IEC framed

How it works

The AI interprets. The platform protects.

Every step narrows what the system is allowed to do. The AI never connects directly to production systems or a raw data store.

In plain English: the model can help form the question, but it cannot decide who may see the answer. Access is checked below the AI each time data is requested.

What clients can expect

Security built into the path to every answer.

01

Access is checked every time

Entra ID confirms who is asking. OpenFGA applies the client's hierarchy - such as portfolio, channel, region, and tenant - before the query runs.

02

Sensitive payment data stays protected

Cardholder account numbers are tokenized before analytics. Ask Nanci works with protected data and does not query live payment-processing systems.

03

The AI has one approved route to data

The model can use only approved tools. The governed data layer runs only authorized, read-only queries against Microsoft Fabric.

04

Trusted answers stay consistent

When a user pins an answer, Ask Nanci saves the exact query. The same business logic runs again while each user's access rules are still applied.

05

Prompts and responses are inspected

Content-safety and data-loss controls inspect unsafe instructions and prevent protected information from appearing in an answer.

06

Activity is monitored

Security monitoring supports alerting, investigation, and response across the application, API, AI, and analytics layers.

Security toolsets

Purposeful controls, clearly placed.

Each product has a defined job. No single tool - or the AI model itself - is expected to provide all security.

Entra ID and PIM

User identity, least privilege, and protected administrative access.

Azure Front Door and APIM

Traffic protection, rate limits, quotas, timeouts, and usage controls.

OpenFGA

Fine-grained access rules based on the user and client hierarchy.

Azure AI Content Safety

Checks for unsafe prompts and responses.

Purview DLP and Key Vault

Protection for sensitive data, secrets, and protected settings.

Defender, Monitor, and Sentinel

Security signals, alerts, investigation, and incident response.

Security approach

Guided by payment and AI security practices.

PCI DSS

Guides how cardholder data is protected, separated, monitored, and kept outside the AI experience.

OWASP

Helps us address common AI application risks such as prompt attacks, sensitive-data exposure, unsafe output, and excessive access.

MITRE ATLAS

Helps us test how an attacker may target AI systems, tools, models, or data - and prepare defenses and response steps.

NIST AI RMF

Guides how we identify, measure, manage, and monitor AI risks throughout the service lifecycle.

ISO/IEC 42001 and 23894

Guides clear ownership, documented controls, supplier oversight, regular review, and continued improvement.

These sources guide the security program. Controls are considered complete only after the configuration and test evidence have been reviewed by Security.
